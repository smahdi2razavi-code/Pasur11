# راه‌اندازی سرور پاسور ۱۱ روی پارس‌پک — ۰ تا ۱۰۰

کد سرور (`server.js`) **هیچ وابستگی بیرونی ندارد** و روی هر میزبانی اجرا می‌شود.
این راهنما مخصوص پارس‌پک است.

---

## ⚠ نکتهٔ حیاتی: سرور حتماً باید HTTPS داشته باشد

بازی تو داخل اپ با آدرس امن (`https://`) اجرا می‌شود. مرورگر اندروید **اجازه نمی‌دهد**
یک صفحهٔ امن به سرور غیرامن (`http://`) وصل شود. پس:

> ❌ `http://185.xx.xx.xx:3000` → کار **نمی‌کند**
> ✅ `https://api.yourdomain.ir` → کار می‌کند

یعنی به یک **دامنه + گواهی SSL** نیاز داری. در روش الف این خودکار است.

### 💡 دامنهٔ رایگان بدون ثبت‌نام (اگر نمی‌خواهی دامنه بخری)
سرویس رایگان **sslip.io** هر آی‌پی را خودکار به یک دامنه تبدیل می‌کند — بدون
ثبت‌نام، بدون هزینه، بدون احراز هویت. کافی است نقطه‌های آی‌پی را خط تیره کنی:

| آی‌پی سرور | دامنهٔ آمادهٔ تو |
|---|---|
| `94.184.36.13` | `94-184-36-13.sslip.io` |

این دامنه از همان لحظه کار می‌کند و **گواهی SSL رایگان هم برایش صادر می‌شود**.
پس در دستور نصب، همین را به‌جای دامنه بده:
```bash
bash setup.sh 94-184-36-13.sslip.io
```
> نکته: اگر روزی سرورت را عوض کردی، دامنه هم بر اساس آی‌پی جدید عوض می‌شود و باید
> یک خط آدرس را در بازی به‌روز کنی. اگر بعداً دامنهٔ اختصاصی خریدی، فقط اسکریپت را
> دوباره با دامنهٔ جدید اجرا کن.

# روش الف (پیشنهادی) — هاست ابری Node.js پارس‌پک

ساده‌ترین راه، بدون نیاز به دانش سرور. HTTPS خودکار داده می‌شود.

## گام ۱ — خرید سرویس
1. برو به: https://parspack.com/paas/nodejs
2. سرویس **هاست ابری Node.js** را بگیر (کوچک‌ترین پلن کافی است).

## گام ۲ — ساخت برنامه
1. وارد پنل پارس‌پک شو → بخش سرویس‌های ابری → **ایجاد برنامهٔ جدید**.
2. **نوع:** `Node.js` — نسخهٔ `18` یا بالاتر.
3. یک نام بگذار، مثلاً `pasur11`.

## گام ۳ — آپلود کد
سه فایل زیر را از پوشهٔ `server` این پروژه آپلود کن (یا از طریق Git وصل کن):
- `server.js`
- `package.json`
- `liara.json` را **لازم نداری** (مخصوص لیاراست).

پارس‌پک با دیدن `package.json` خودش `npm start` را اجرا می‌کند.

## گام ۴ — متغیرهای محیطی
در تنظیمات برنامه، این‌ها را اضافه کن:

| نام | مقدار |
|---|---|
| `ADMIN_KEY` | یک رمز قوی بساز (مثلاً `Pasur11_x9K2mQ7z`) و جای امن نگه دار |
| `DATA_FILE` | `/app/data/data.json` (یا مسیر دیسک دائمی که پنل می‌دهد) |

> `ADMIN_KEY` جلوی سوءاستفاده را می‌گیرد؛ بدون آن کسی نمی‌تواند به کاربران سکه یا VIP بدهد.

## گام ۵ — دیسک دائمی (مهم)
اگر پنل گزینهٔ **«دیسک/فضای ذخیره‌سازی دائمی»** دارد، یکی بساز و مسیرش را
`/app/data` بگذار؛ وگرنه با هر بار استقرار مجدد، جدول رتبه‌بندی پاک می‌شود.

## گام ۶ — تست
آدرسی که پنل می‌دهد (مثلاً `https://pasur11.parspack.app`) را با `/health` باز کن:
```
https://pasur11.parspack.app/health
```
اگر `{"ok":true,...}` دیدی، سرور سالم است ✅

## گام ۷ — وصل‌کردن بازی
در `index.html` این خط را پیدا کن و آدرس سرورت را بگذار:
```js
const FIREBASE_DB_URL='https://pasur11.parspack.app';
```
سپس فایل را در `app/src/main/assets` جایگزین کن → `Build → Clean Project` → **Run**.

# روش ب — سرور مجازی (VPS) لینوکس پارس‌پک

اگر VPS گرفتی، مراحل بیشتر است ولی کنترل کامل داری. **به یک دامنه نیاز داری.**

## گام ۱ — خرید و اتصال
1. یک **VPS لینوکس (اوبونتو ۲۲.۰۴)** از https://parspack.com/vps/linux بگیر.
2. با SSH وصل شو (از کامپیوترت):
```bash
ssh root@آی‌پی‌سرور
```

## گام ۲ — نصب Node.js
```bash
apt update && apt upgrade -y
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs
node -v          # باید v20.x نشان دهد
```

## گام ۳ — قرار دادن کد سرور
```bash
mkdir -p /opt/pasur11 && cd /opt/pasur11
```
حالا فایل‌های `server.js` و `package.json` را در این پوشه بگذار (با WinSCP، FileZilla
یا دستور `nano server.js` و کپی‌کردن محتوا).

## گام ۴ — اجرای دائمی با pm2
```bash
npm install -g pm2
cd /opt/pasur11
ADMIN_KEY="رمز_قوی_تو" DATA_FILE="/opt/pasur11/data.json" PORT=3000 pm2 start server.js --name pasur11
pm2 save
pm2 startup        # دستوری که می‌دهد را کپی و اجرا کن تا بعد از ریستارت هم بالا بیاید
```
تست محلی:
```bash
curl http://127.0.0.1:3000/health
```

## گام ۵ — دامنه
یک دامنه بگیر (مثلاً از خود پارس‌پک) و یک رکورد **A** بساز:
```
api.yourdomain.ir  →  آی‌پی سرورت
```
چند دقیقه صبر کن تا اعمال شود.

## گام ۶ — Nginx + گواهی SSL رایگان
```bash
apt install -y nginx certbot python3-certbot-nginx

cat >/etc/nginx/sites-available/pasur11 <<'EOF'
server {
    listen 80;
    server_name api.yourdomain.ir;
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
EOF

ln -s /etc/nginx/sites-available/pasur11 /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx

# گواهی SSL رایگان (دامنه را با مال خودت عوض کن)
certbot --nginx -d api.yourdomain.ir
```
Certbot خودش HTTPS را فعال و تمدید خودکار می‌کند.

## گام ۷ — فایروال
```bash
ufw allow OpenSSH
ufw allow 'Nginx Full'
ufw --force enable
```

## گام ۸ — تست و اتصال بازی
در مرورگر: `https://api.yourdomain.ir/health` → باید `{"ok":true,...}` بدهد.
بعد در `index.html`:
```js
const FIREBASE_DB_URL='https://api.yourdomain.ir';
```

# 🛡️ نسخهٔ تازهٔ سرور — چه چیزهایی اضافه شد

بعد از اجرای `update.sh` این‌ها فعال می‌شوند:

## ۱) پشتیبان خودکار روزانه
هر شب ساعت **۳:۲۰** یک نسخهٔ فشرده از داده‌ها در `/opt/pasur11/backups/`
ذخیره می‌شود و **۱۴ روز اخیر** نگه داشته می‌شود.

- قبل از پشتیبان‌گیری، سالم‌بودن فایل بررسی می‌شود (از نسخهٔ خراب پشتیبان نمی‌گیرد)
- در پنل، تب **ابزار** تاریخ آخرین پشتیبان را نشان می‌دهد
- گرفتن دستی: `bash /opt/pasur11/backup.sh`
- دیدن فهرست: `ls -lh /opt/pasur11/backups/`

**بازگرداندن یک نسخه:**
```
pm2 stop pasur11
gunzip -c /opt/pasur11/backups/data-1404-05-18.json.gz > /opt/pasur11/data.json
pm2 start pasur11
```

> `update.sh` هم قبل از هر به‌روزرسانی یک نسخهٔ اضطراری در
> `backups/data-before-update.json.gz` می‌گذارد.

## ۲) محافظت در برابر خرابکاری
| محافظت | مقدار |
|---|---|
| سقف درخواست از هر IP | ۳۰۰ در دقیقه (بیشتر → خطای ۴۲۹) |
| سقف تعداد کاربر | ۱۰۰٬۰۰۰ |
| سقف حجم فایل داده | ۱۰۰ مگابایت |
| سقف درخواست دوستی هر کاربر | ۵۰ |
| شناسهٔ کاربر | فقط قالب `11-123456` پذیرفته می‌شود |
| جام / سطح | حداکثر ۱٬۰۰۰٬۰۰۰ و ۵۰۰ |

مقادیر غیرممکن (مثل یک میلیارد جام) دیگر در جدول رتبه‌بندی ثبت نمی‌شوند.

اگر خواستی سقف‌ها را عوض کنی، در pm2 متغیر بده:
`RATE_PER_MIN`، `MAX_USERS`، `MAX_DATA_MB`.

## ۳) ورود امن پنل مدیریت
سه لایه روی هم:

**الف) توکن نشست به‌جای کلید.** پنل یک بار کلید را به `POST /auth` می‌دهد و
یک **توکن ۸ ساعته** می‌گیرد. بعد از آن همهٔ درخواست‌ها با هدر `X-Admin-Token`
می‌روند و کلید اصلی دیگر اصلاً روی شبکه نمی‌رود. توکن **فقط در حافظهٔ سرور**
می‌ماند (با ری‌استارت پاک می‌شود) و **به IP همان دستگاه گره خورده** است؛
پس اگر کسی توکن را بدزدد، از IP دیگری کار نمی‌کند.
`DELETE /auth` توکن را همان لحظه باطل می‌کند (دکمهٔ «قفل کردن» پنل).

**ب) قفل شدن بعد از تلاش‌های ناموفق.** ۱۰ کلید اشتباه از یک IP → آن IP
**۱۵ دقیقه** قفل می‌شود، حتی اگر بعدش کلید درست بزند. پاسخ سرور تعداد
تلاش باقی‌مانده را هم می‌گوید. مقایسهٔ کلید **زمان‌ثابت** است تا از روی
سرعت پاسخ نشود کلید را حدس زد.

**ج) فهرست IP مجاز (اختیاری).** اگر متغیر `ADMIN_IPS` را بدهی، فقط از همان
IPها می‌شود وارد پنل شد:

```
ADMIN_IPS=1.2.3.4,5.6.7.8
```

خالی بگذاری = محدودیتی نیست. ترافیک خود بازی هیچ‌وقت تحت تأثیر این تنظیم
نیست — فقط نقطه‌های مدیریتی.

> هدر `X-Admin-Key` و روش قدیمی `?key=` هنوز کار می‌کنند تا پنل‌های قدیمی
> نخوابند.

### سمت پنل
کلید مدیریت در مرورگر **خام ذخیره نمی‌شود**: با رمزی که خودت می‌سازی
(PBKDF2 با ۲۱۰٬۰۰۰ دور + AES-GCM) رمز می‌شود. پنل بعد از ۱۵ دقیقه بی‌کاری
خودکار قفل می‌شود، و کارهای برگشت‌ناپذیر تأیید تایپی می‌خواهند.

## ۴) لیگ هفتگی
هر هفته (دوشنبه‌ها) جدول هفتگی صفر می‌شود و **۱۰ نفر برتر خودکار جایزه
می‌گیرند**: ۳٬۰۰۰ / ۲٬۰۰۰ / ۱٬۲۰۰ / ۸۰۰ / ۶۰۰ / ۵۰۰ / ۴۰۰ / ۳۰۰ / ۲۰۰ / ۱۵۰ سکه.
جایزه در اولین همگام‌سازی بازی به حساب بازیکن اضافه می‌شود و یک نامه هم می‌گیرد.
امتیاز کل (all-time) دست‌نخورده می‌ماند.

## ۵) شمارندهٔ قیف
بازی هر مرحله را **یک‌بار** برای هر نصب می‌فرستد (نصب، ساخت پروفایل، بازی اول،
سه بازی، ده بازی، فروشگاه، خرید). هیچ اطلاعات شخصی نمی‌رود — فقط یک شمارنده.
نتیجه در داشبورد پنل به‌صورت نمودار قیف دیده می‌شود.

## ۶) دفتر ثبت کارها
هر کار مدیریتی با زمان و IP ثبت می‌شود (۵۰۰ مورد آخر) و در تب **ابزار** دیده
می‌شود. عملیات گروهی هم **قابل برگرداندن** است.

## نقاط تازهٔ سرور (همه با کلید مدیریت)
| مسیر | کار |
|---|---|
| `GET /stats` | آمار کلی، نمودار، قیف، وضعیت پشتیبان، لیگ |
| `GET /control` | همهٔ دستورها با یک درخواست |
| `DELETE /control/<id>` | لغو دستورهای در انتظار یک کاربر |
| `GET /sessions` | بازی‌های دو نفرهٔ فعال |
| `PUT /bulk` | عملیات گروهی |
| `DELETE /bulk` | برگرداندن آخرین عملیات گروهی |
| `GET /audit` | دفتر ثبت کارها |
| `GET /export` | پشتیبان کامل |
| `GET /broadcast/log` | تاریخچهٔ اعلان‌ها |
| `GET /leaderboard/_week` | وضعیت لیگ هفتگی |
| `POST /auth` | گرفتن توکن نشست ۸ ساعته (با کلید) |
| `DELETE /auth` | باطل‌کردن توکن (قفل کردن پنل) |
